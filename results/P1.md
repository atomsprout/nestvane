# P1 真机验证

2026-11-18。iPhone 11，iOS 26.0.1，Xcode 27.2（27B52），Release 构建。通过开发签名安装，并通过 CoreDevice 正常启动，未附加调试器。AOT 入口编进 iOS 可执行文件的 `__TEXT,__text`。两份 ELF 随包作为数据资源。

| 用例 | 单步中位数 | 块解释中位数 | AOT 中位数 | AOT 对块解释 |
| --- | ---: | ---: | ---: | ---: |
| 算术循环 | 2.327 ms | 1.167 ms | 0.041 ms | 28.328× |
| 跨客体页读写循环 | 4.259 ms | 1.830 ms | 0.261 ms | 7.024× |

各模式计时 20 次，轮换顺序。计时涵盖入口匹配、分派和客体执行，不含 ELF 装载。设备热状态保持 nominal。过程峰值 RSS 39,878,656 字节，包含 UIKit 等宿主开销。

五个用例比对了最终寄存器、PC、SP、已执行指令数、停止原因、输出和映射内存。包括算术、成功跨页访问、重定基址、指令变化导致 AOT 回退、AOT 块内访问异常。两份原始 ELF 也通过独立 ARM64 Linux 内核运行，并在 exit 系统调用处读回 X19 校验值。

采用同配置、未签名 Release 对照构建，仅将预编译表替换为空表。两个 AOT 入口和对应表让当前 Mach-O 增加 576 字节，其中 `__text` 增加 372 字节。这是该小样本的增量，不能推算 Android 系统库的翻译体积。

Linux 参考使用 QEMU 11.1.2 和 Alpine ARM64 virt 内核，内核 SHA-256 为 `4ac63d06e6cf5820905ffa7741292cfbe90fb0cf1edba4c42e871f6daf699437`。两份 ELF 的 SHA-256 分别为 `a271f0d4b167122faf77e76f5c3b58a9c5992b19a62fc1c69bb2e0dbf3ac2610` 和 `9de5a98a5467d464feed1a2082a2953d4f466300a7b9e3e4e7f6691acfc78347`。

结论是**静态签名的 AOT 和解释器能在普通 iPhone 上协同运行**。本轮 AOT 专门编译两个自制热点，解释器也仅覆盖夹具指令。尚未验证 Android 17 的动态链接、线程、Binder、实际 Android 启动或 App 交互性能。下一项验收是运行 Android 17 的 `linker64` 和一个依赖 Bionic 的测试 ELF。
